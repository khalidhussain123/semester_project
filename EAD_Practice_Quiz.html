⚛️ React Fundamentals
JSX, Components, Props, State, Virtual DOM — the building blocks of React.

📘 Key Concepts

  • React is a JavaScript Library (NOT a framework) — handles only the View layer.
  • JSX = JavaScript XML — HTML-like syntax compiled by Babel into React.createElement() calls.
  • Component names MUST start with a Capital Letter — lowercase = HTML tag.
  • React DOM uses camelCase: onClick, className, onChange.
  • The smallest building blocks are Elements (not components). Elements are immutable.
  • ⚠ TRAP: useState uses Array destructuring — NOT object destructuring.
  • Data flows top-down (parent → child only). Props are read-only.
  • The Virtual DOM is an in-memory copy of the real DOM — React syncs changes efficiently.
Q1 ⚠ TRAP React is a JavaScript ___ for building user interfaces.
✅ Library — React is a UI library, not a framework. A framework (like Angular) provides the whole structure; React only handles the view layer. This is a classic exam trap!
Q2 ⚠ TRAP Which activity do we perform while declaring useState?
✅ Array destructuring — const [count, setCount] = useState(0) uses array destructuring (square brackets). useState returns an array of [value, setter], not an object.
Q3 JSX stands for?
✅ JavaScript XML — JSX is HTML-like syntax inside JavaScript. Babel compiles it into React.createElement() calls. Without Babel, browsers can't read JSX directly.
Q4 ⚠ TRAP React DOM uses ___ case property naming convention?
✅ Camel Case — React DOM uses camelCase for all attributes: onClick (not onclick), className (not class), onChange, htmlFor. This is different from plain HTML.
Q5 ⚠ TRAP Which are the smallest building blocks of React apps?
✅ Elements — React Elements are the smallest building blocks (e.g., const el = <h1>Hello</h1>). Components are made of elements. Elements are immutable — you can't change them after creation.

🪝 Hooks & Effects
useState, useEffect, useRef, useContext — React's built-in Hooks system.

📘 Key Concepts

  • useEffect with [] runs ONCE after initial render (like componentDidMount).
  • useEffect with [dep] runs on initial render AND whenever dep changes.
  • useEffect with no array runs after EVERY render.
  • ⚠ TRAP: An effect ALWAYS runs on the initial render — regardless of the dependency array.
  • useRef returns { current: initialValue } — does NOT trigger re-render.
  • Hooks CANNOT be called inside if, loops, or nested functions — only at the top level.
  • Rules of Hooks: Only call at top level. Only call from React functions.
  • ⚠ TRAP: You CANNOT mark useEffect callback as async — use an inner async function.
Q1 ⚠ TRAP An effect ALWAYS runs on the ___?
✅ Initial render, always — Every useEffect runs at least once (on mount). The dependency array only controls subsequent runs. So useEffect(fn, []) still runs once on first render.
Q2 ⚠ TRAP What does useRef return?
✅ {current: initialValue} — useRef returns a mutable ref object with a .current property. Unlike useState, changing ref.current does NOT trigger a re-render. Used for DOM access or persisting values between renders.

🗺️ React Router
SPA routing, nested routes, dynamic routes, navigation hooks.

📘 Key Concepts

  • React Router v6 uses <Routes> (NOT Switch — that was v5).
  • ⚠ TRAP: useNavigate() replaces useHistory() from v5.
  • useParams() reads dynamic URL segments like :id.
  • <Outlet /> is a placeholder in parent — child routes render there.
  • Use <Link> not <a> — anchor tags cause full page reload.
  • <NavLink> automatically adds an active class; <Link> does NOT.
  • 404 fallback: <Route path="*"> — must be placed last in Routes.
Q1 ⚠ TRAP Which component is used to define routes in React Router v6?
✅ Routes — In v6, <Routes> replaced <Switch>. Routes renders the FIRST matching route. Switch was v5 — a very common exam trap!
Q2 ⚠ TRAP How do you navigate programmatically in React Router v6?
✅ useNavigate() — This replaced useHistory() in v6. Usage: const nav = useNavigate(); nav('/dashboard');. nav(-1) goes back like browser back. useHistory was v5.
Q3 What is an Outlet in React Router?
✅ Placeholder for child routes — When you have nested routes, the parent component uses <Outlet /> to say "render the matching child route here". Like a slot in the layout.
Q4 Which hook reads URL parameters from a dynamic route?
✅ useParams() — For a route like /users/:id, the hook const { id } = useParams() reads the :id segment from the URL. Note: useParams returns strings, so use parseInt() for numbers.
Q5 Match the React Router component/hook with its purpose.

Link → No reload. NavLink → Adds active class (useful for nav menus). useSearchParams → Query strings like ?page=2. useParams → Dynamic segments like :id.
🏪 Redux & Reducers
useReducer, Redux Toolkit, actions, pure functions, state management.

📘 Key Concepts

  • Redux flow: UI → dispatch(action) → Reducer → new State → Store → UI re-renders.
  • Every action MUST have a type property. payload is optional.
  • Reducer must be a pure function: same input → same output, no side effects.
  • useReducer returns [state, dispatch] — NOT [state, action].
  • ⚠ TRAP: Redux Toolkit (RTK) uses Immer — direct mutation IS safe inside createSlice.
  • useSelector() reads from Redux store; useDispatch() sends actions.
  • Single source of truth: ONE store for the entire app.
Q1 ⚠ TRAP What is the correct flow of data in Redux?
✅ Action → Dispatcher → Store → View — The Flux/Redux pattern: UI dispatches an Action → Reducer processes it → Store updates → View re-renders. The reducer never talks directly to UI — it's always one-way data flow.
Q2 ⚠ TRAP What does useReducer return?
✅ [state, dispatch] — Just like useState returns [value, setter], useReducer returns [state, dispatch]. You call dispatch({type: 'INCREMENT'}) to trigger a state change through the reducer.
Q3 A reducer function must be?
✅ Pure function — A pure function: same inputs → same output, no side effects (no API calls, no random). This is required so Redux can predict state changes and enable time-travel debugging.
Q4 ⚠ TRAP What must every Redux action have?
✅ type — Every Redux action is a plain JS object with a required type property (a string like 'INCREMENT'). payload is optional — used to pass additional data. The reducer uses action.type in a switch statement.

🟢 Node.js
Runtime, Event Loop, Modules, File System, npm, Nodemon.

📘 Key Concepts

  • Node.js is a JavaScript Runtime built on Chrome's V8 engine — NOT a language or framework.
  • Node is single-threaded but handles concurrency via the Event Loop and non-blocking I/O.
  • CommonJS uses require(). ES Modules use import. Cannot mix without config.
  • ⚠ TRAP: fs.readFileSync() is BLOCKING — avoid in production servers.
  • Built-in modules: fs, path, http, events, os, crypto.
  • Nodemon is a DEV tool only — auto-restarts server on file changes. Never use in production.
  • ⚠ TRAP: node_modules/ should NEVER be pushed to Git — add to .gitignore.
Q1 Node.js is built on which JavaScript engine?
✅ V8 — V8 is Google's high-performance JavaScript engine (used in Chrome). Node.js uses V8 to run JS outside the browser. SpiderMonkey is Mozilla's (Firefox). Chakra was Microsoft's. JavaScriptCore is Apple's (Safari).
Q2 ⚠ TRAP Node.js is single-threaded. How does it handle concurrent requests?
✅ Event Loop + non-blocking I/O — Node offloads I/O operations (file reads, DB queries, API calls) to the system, then continues processing. When I/O is done, the callback enters the event queue. This allows handling thousands of concurrent connections on one thread.
Q3 Which module handles file reading/writing in Node.js?
✅ fs — The fs (File System) module provides readFile(), writeFile(), readFileSync(), etc. Use async versions in production. path handles file paths. http creates servers. os reads system info.
Q4 What is the correct way to import a built-in module in CommonJS?
✅ require('http') — CommonJS (the default in Node.js) uses require(). ES Module syntax (import) also works but requires "type":"module" in package.json or .mjs extension. They cannot be freely mixed.
Q5 What does Nodemon do?
✅ Auto-restarts on file changes — Nodemon monitors your project files and restarts the Node.js server automatically when changes are saved. Install as devDependency: npm install nodemon --save-dev. NEVER use in production.

🚀 Express.js
Routing, Middleware, RESTful APIs, Request & Response.

📘 Key Concepts

  • Middleware = function with (req, res, next). MUST call next() or the request hangs.
  • ⚠ TRAP: express.json() is REQUIRED to read JSON body — without it, req.body is undefined.
  • Route params → req.params.id. Query strings → req.query.key. Body → req.body.
  • HTTP status: 200=OK, 201=Created, 204=No Content, 400=Bad Request, 404=Not Found, 500=Server Error.
  • Error middleware MUST have exactly 4 params: (err, req, res, next).
  • Middleware ORDER matters — app.use() runs in the order defined. Define error middleware LAST.
Q1 What is middleware in Express.js?
✅ (req, res, next) function — Middleware sits between the request and response. It can read/modify req and res, run code, and then either call next() to pass control forward, or end the response.
Q2 ⚠ TRAP What happens if middleware does NOT call next()?
✅ Request-response cycle stops — The client will hang forever waiting for a response that never comes. You must either call next() OR send a response (res.send(), res.json()) in every middleware branch.
Q3 Which HTTP status code means 'Created'?
✅ 201 Created — Returned when a POST request successfully creates a new resource. 200=OK (GET/PUT). 204=No Content (DELETE). 404=Not Found. 500=Server Error. Remember: 2xx = success, 4xx = client error, 5xx = server error.
Q4 ⚠ TRAP Which middleware is needed to read JSON request body?
✅ express.json() — Without this, req.body will be undefined for JSON requests. Add it as: app.use(express.json()) before your routes. For HTML form data, use express.urlencoded({extended:true}).
Q5 How do you access route parameters in Express?
✅ req.params.id — For route /users/:id, the ID is in req.params.id. Remember: req.params = URL segments, req.query = query strings (?key=val), req.body = request body (POST/PUT).
Q6 Match the HTTP method with its REST action and typical status code.
POST /api/users
GET /api/users
DELETE /api/users/:id
POST → 201 Created. GET → 200 OK. DELETE → 204 No Content (success but nothing to return). PUT/PATCH → 200 OK with updated resource.
🍃 MongoDB & Mongoose
NoSQL documents, collections, CRUD, Schema, ODM vs ORM.

📘 Key Concepts

  • MongoDB is a NoSQL Document database — stores BSON (Binary JSON).
  • SQL Table = MongoDB Collection. SQL Row = MongoDB Document.
  • Mongoose is an ODM (Object Document Mapper). ORM is for SQL/relational databases.
  • ⚠ TRAP: findByIdAndUpdate() does NOT return updated doc by default — add { new: true }.
  • ⚠ TRAP: Without $set, the entire document is replaced when updating.
  • MongoDB uses _id as primary key — auto-generated ObjectId if not provided.
  • Default MongoDB port: 27017.
Q1 What is the equivalent of a SQL 'table' in MongoDB?
✅ Collection — SQL Table → MongoDB Collection. SQL Row → Document. SQL Column → Field. SQL Primary Key → _id (ObjectId). Know this mapping cold for the exam.
Q2 ⚠ TRAP What is the difference between ORM and ODM?
✅ ORM=SQL, ODM=Document — ORM (Object Relational Mapper) maps objects to SQL tables (e.g., Sequelize, TypeORM). ODM (Object Document Mapper) maps objects to MongoDB documents (e.g., Mongoose).
Q3 What is Mongoose?
✅ ODM for MongoDB — Mongoose sits on top of the raw MongoDB driver and adds Schema validation (at the application level), model methods, query chaining, middleware hooks (pre/post save), and a cleaner API.
Q4 ⚠ TRAP Which Mongoose method returns the UPDATED document?
✅ findByIdAndUpdate with {new:true} — By default, findByIdAndUpdate returns the original document (before update). Adding { new: true } as the third argument makes it return the updated document. This is a classic exam trap!
Q5 Which MongoDB operator increments a numeric field?
✅ $inc — Used as: { $inc: { visits: 1 } }. Other update operators: $set (set field), $unset (remove field), $push (add to array). Remember: without $set, the entire doc is replaced!
Q6 Match the SQL concept with its MongoDB equivalent.
SQL Table
SQL Row
Primary Key
SQL Table → Collection. SQL Row → Document. SQL Column → Field. Primary Key → _id (ObjectId). MongoDB auto-generates a unique ObjectId for each document's _id.
⏳ Promises & Async/Await
Promise methods, .then/.catch, async/await, error handling.

📘 Key Concepts

  • Promise.resolve(val) — creates an already-resolved Promise with value.
  • .then() — handles a fulfilled (resolved) Promise; returns a new Promise.
  • .catch() — handles rejected Promises (errors); like try/catch for async.
  • async function — declares a function that always returns a Promise.
  • await — pauses execution inside an async function until the Promise settles.
  • Promise.all([]) — waits for ALL promises; rejects if any one fails.
  • Promise.race([]) — resolves/rejects as soon as the FIRST promise settles.

Promise.resolve() wraps a value in a resolved Promise. .then() chains on success. .catch() handles errors. async marks a function as asynchronous (always returns Promise). await suspends the function until the Promise resolves — can only be used inside async functions.

Q3 What does Promise.race([]) do?
✅ First to settle (resolve OR reject) — race() is like a race: first one done wins. Even if it rejects. Compare: all() = all must resolve. any() = first to FULFILL (ignores rejections until all reject). allSettled() = wait for all, regardless of outcome.
Q4 Which keyword is used to pause execution inside an async function?
✅ await — await can only be used inside async functions. It pauses that function's execution until the awaited Promise resolves. Other code continues to run in the meantime (non-blocking). yield is for generators, not Promises.
Q5 How do you handle errors with async/await?
✅ try...catch — With async/await, wrap your awaited calls in try { } catch(err) { }. If the awaited Promise rejects, the error is caught. You can also chain .catch() on the async function call itself, but try/catch is the idiomatic approach.
Q6 What does an async function always return?
✅ A Promise — Even if you write async function f() { return 42; }, calling f() returns Promise.resolve(42), not 42 directly. This is what allows await f() to work.

Cross-topic questions — covers all EAD topics.
Q1 Which git command creates a new branch AND switches to it in one step?
✅ git checkout -b — The -b flag means "create new branch and switch". Equivalent modern syntax: git switch -c new-feature. git branch new-feature creates without switching. git switch new-feature switches to an existing branch.
Q2 Node.js is primarily used for?
✅ I/O-bound apps — Node's event loop and non-blocking I/O make it ideal for web servers, REST APIs, real-time apps (chat, gaming), microservices. NOT suitable for CPU-heavy tasks (use Python, C++ threads, or Worker threads for those).
Q3 How do you access query string parameters in Express? (e.g., /search?q=ali)
✅ req.query.q — Query strings come after the ? in the URL. req.query parses them automatically. req.params is for URL segments like :id. req.body is for the request body (POST/PUT with middleware).
Q4 What HTTP status code should be returned when a resource is NOT found?
✅ 404 Not Found — Standard status codes: 200=OK, 201=Created, 204=No Content, 301=Moved Permanently, 400=Bad Request, 401=Unauthorized, 403=Forbidden, 404=Not Found, 500=Internal Server Error.
Q5 What is the role of package.json in a Node project?
✅ Project manifest — package.json is the heart of a Node project. It lists: dependencies (production), devDependencies (dev-only), scripts (npm start, npm run dev), main (entry point), name, version, etc.
Q6 ⚠ TRAP Which third-party middleware is used for HTTP request logging in Express?
✅ morgan — morgan logs HTTP request details (method, URL, status, response time). Others: cors handles Cross-Origin Resource Sharing. helmet sets security HTTP headers. multer handles file uploads. winston is general-purpose logging (not HTTP-specific).
Q7 In MongoDB/Mongoose, which form enctype is required for file uploads?
✅ multipart/form-data — This enctype is required when your form uploads files. Regular forms use application/x-www-form-urlencoded (default). Multer middleware in Express handles multipart/form-data requests.
Q8 ⚠ TRAP What does git stash do?
✅ Temporarily saves uncommitted changes — git stash saves your working directory changes aside so you have a clean state to switch branches. Later: git stash pop restores AND removes from stash list. git stash apply restores but keeps in stash list.
